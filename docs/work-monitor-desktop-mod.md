# work-monitor: Claude desktop side pane (mod)

A Claude Code **mod** (function-hooks plugin) that draws a pane beside the chat: local token usage, active/failed CI, my open MRs, review-requested MRs. Polls GitLab every 60s; `/work-monitor` reopens it. Deterministic: one HTTP call and one local Python scan per poll, no MCP or model calls.

- **Location**: `.claude/mods/work-monitor/` in the hub, published by the directory marketplace `local-mods` (`.claude/mods/.claude-plugin/marketplace.json`) and enabled in `.claude/settings.json`. Sessions load the cached copy under `~/.claude/plugins/cache/local-mods/work-monitor/<version>/`, so after an edit bump `version` in `plugin.json`, run `claude plugin marketplace update local-mods` and `claude plugin update work-monitor@local-mods --scope project`, then restart the sessions.
- **Files**: `hooks/register.tsx` (pane, poll, `/work-monitor`), `hooks/gitlab.ts` (data), `hooks/origin.ts` (session lookup on click), `hooks/usage.ts` (token scan), `types/index.d.ts` (`$.state` contract), `tests/pane.test.tsx`.
- **Tokens panel** (0.4.0, top of the pane): `hooks/usage.ts` runs a Python scan each poll over the transcripts in `~/.claude/projects` changed in the last 5 hours and shows weighted tokens for the last hour and the last 5 hours, then the 10 sessions that used most in the 5 hours (worktree name, or `claude-mem observer`) and one `N other sessions` row summing the rest. Weights: cache reads 0.1, cache writes 1.25, output 5; each message id counts once. The header also shows `~N%`: the 5-hour figure over `WINDOW_BUDGET` = 26M weighted tokens, calibrated from one reading (1.81M weighted = 7% on 2026-11-18). Rough: the plan counts models differently and its window starts on the hour of the first message, while the panel's is a rolling 5 hours. Recalibrate from the app's usage report: weighted tokens since (reset − 5h) ÷ percent. About 0.1s for 50 MB.
- **Session button**: no sessions list (removed in 0.2.0). Each MR row has a `Session` button (0.3.0) that searches only on click: `hooks/origin.ts` greps `~/.claude/projects` for the MR URL (about 1s over 3 GB, claude-mem observer and subagent transcripts excluded), takes the transcript naming it most, maps its cli session id to a `local_*.json` record under `~/.config/Claude/claude-code-sessions/` and `xdg-open`s `claude://claude.ai/epitaxy/<local id>`. `$.process.run` is not a tool call, so claude-mem never sees it.
- **Notion link** (0.6.0): each MR row shows a `Notion` link when the MR description holds a Notion URL (`notion.so` or `app.notion.com`, first match, regex in `hooks/gitlab.ts`). The description comes from the same GraphQL query, so no Notion call. A description that names the ticket by number only (`Notion 4226`) gets no link: on 2026-11-26 only 2 of 10 open MRs had a URL.
- **Never call an MCP tool from the poll**: until 0.1.1 the mod called `ccd_session_mgmt.list_sessions` every 60s in every open session. claude-mem observes each tool call, so each 31 KB result went to its Sonnet 4.5 observer: about 5M effective tokens per hour with no interactive session (found 2026-11-17).
- **GitLab**: one GraphQL POST to `gitlab.com/api/graphql` — `currentUser { authoredMergeRequests / reviewRequestedMergeRequests (state: opened, sort: UPDATED_DESC) { iid title description webUrl draft project{fullPath} headPipeline{status path} } }`. There is no cross-project "my running pipelines" endpoint, so "active CI" = MR head pipelines in CREATED/PENDING/RUNNING/…
- **Token**: the desktop app does not source `~/.bashrc`, so `$.env.get('GITLAB_TOKEN')` is usually empty; the mod parses the `export GITLAB_TOKEN=` line from `~/.bashrc` (same trick as `.claude/hub-env`).
- **Dev loop**: `claude plugin validate <dir>`; `tsc -p` with a tsconfig outside the mod including the skill's `types/claude-code.d.ts`; `claude plugin test <dir>` (mock `http.fetch`, `env.get` with `on(...) => ({ value })`, then `ui.press({ key: 'refresh' })`).
- **Where a mod can draw** (checked in the 2.1.321 types): `Pane` (docked beside the transcript, else inline above the prompt), `AbovePrompt` band, transcript rows (`ToolUse`, messages, `Placed`), status line under the prompt, toasts, `Backdrop` behind the conversation (desktop and mobile). There is no slot at the top of the screen; a pinned message goes in the band.
- **Gotchas**: section children must be typed `RenderChildren[]`, not `unknown[]`. In a test, a `Link`'s `text` is its href followed by its label, so match the label with `/Notion$/` and read `props.href`.
