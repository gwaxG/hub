Import graph & code metrics

Summary

Dependency graph

Force-directed import graph — node size is lines of code, colour is layer, arrows point from importer to imported. Hover a node for its metrics; click one to isolate it and its direct neighbours, click the background to reset.

Dependency matrix

Rows import columns, ordered so that dependencies run downstream (importers first). Every ordinary import therefore sits above the diagonal — an amber cell below it is a back-edge, i.e. part of a dependency cycle. Hover any cell for the pair.

Layer coupling

Imports from each layer (row) into each layer (column). This is the matrix an import-linter contract would police: decide which cells are allowed to be non-zero, and everything else becomes a CI failure.

Dependency cycles

Strongly connected components — every member can reach every other, so none of them can be understood, tested, or extracted alone.

    Node metrics

    Ca/Ce fan-in / fan-out · I instability Ce/(Ca+Ce) · A abstractness · Dist |A+I−1|, distance from the main sequence (high = painful to change or useless abstraction) · CC worst cyclomatic complexity · MI maintainability index (<65 is poor) · Churn lines changed in the window · Auth distinct authors (1 = bus factor 1). Click a header to sort.

    Hotspots

    Per file, normalised churn × complexity. Complexity only hurts where the code keeps changing — these files are where reading, testing and reviewing effort pays off most.
